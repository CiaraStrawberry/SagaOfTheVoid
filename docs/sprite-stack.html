Sprite stacking: a look test

Each ship below is a pile of flat pixel-art slices, cut from the game's real 3D models, two slices per pixel of height. Drawing the slices bottom to top, each nudged up a little and all turned to the same angle, fakes a 3D model. Only a prototype: nothing in the game uses it yet. The method follows this sprite-stacking write-up.

Fleet in motion

A low-resolution scene (640 × 360, scaled up with no smoothing; every ship at its true pixel size), roughly how a sprite version of a battle might look. Drag sideways to turn the camera.

One ship up close

Tilt squashes each slice top to bottom, as if the camera leans back from straight down (1 = straight down). Height sets how tall the stack rises (1 = the hull's true height, 0 = a flat sprite). The two sliders are shared with the fleet view. Each ship has two slices per pixel of height, so lowering Height keeps the sides smooth. "Smooth" draws each slice at full screen size instead of on the pixel grid, which looks less like pixel art but keeps fine detail.

The slices for this ship, bottom first, read left to right. The last one is a "lid": the ship as seen from above, so the top of the stack shows the hull's markings.

How the slices were made

A Unity script (tools/bake/Assets/Editor/StackBaker.cs) points a straight-down camera at each ship and moves the near clipping plane down half a pixel at a time. Where the first surface the camera sees is the inside of the hull, that pixel is inside the ship at that height, so it goes in the slice. tools/sprite_stack.py shrinks the 4× renders to the pixel size, colours each slice from the lit top view, darkens the lower slices and cuts the colours to 14 per ship. Fighters are 26 pixels long and the Super-Capital 170.

Known rough edges: the slicing relies on closed hulls, so thin open parts (antennae, fins) can drop out; the team colour is weak after the palette cut; small craft have only 13 to 21 slices.
